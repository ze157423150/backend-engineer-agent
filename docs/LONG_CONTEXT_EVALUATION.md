# 长上下文与自动恢复评测

该入口将真实模型、Docker 文件工具、测试反馈、上下文治理和检查点恢复组合为可重复执行的多轮评测。自动回退由评测执行器负责；终端会话仍使用 `/resume` 等显式恢复操作。

## 已记录结果

**64轮长上下文测试自主运行通过。** 2026-10-18，系统结合自动检查点恢复机制，完成同一组 64 轮访问日志项目任务的全部独立代码验收。模型、任务与 Agent 代码在实验期间固定，没有人工修复或向模型注入失败答案。

| 首次通过的轮次 | 63 |
| 重试后通过的轮次 | 1 |
| 实际轮次尝试 | 65 |

64 个轮末快照通过文件清单校验。第 7—64 轮回放任务的输入文件、测试内嵌输入和 8 字段期望数组经独立核算一致，既有用例保留。过程中成功尝试仍出现过工具失败及一次摘要拒绝，由后续执行处理，不能描述成全程无异常。

这是自动恢复策略下的一次完整实验，不是 64 轮连续无失败通过，也不代表其他任务或模型上的通用成功率。验收覆盖代码契约与回放行为，不自动评价所有自然语言说明和历史审计回答的准确性。记录使用修复完成后的 2.0.0 本地构建；v2.1.0 收录这些修复和整理后的评测入口，并进行发布回归，未为版本号变化重复消耗一次 64 轮模型测试。

## 自动回退规则

- 每次最多 50 次模型调用，每轮默认最多 3 次尝试（首次与最多两次重试）；不设累计 Token 上限，运行前评估所需 API 额度。
- 会话 FAILED、BUDGET_EXHAUSTED 或评测子进程非零退出时，重新复制上一轮成功快照，重新执行同一轮；第 1 轮从种子工作区重建。
- 每轮、每次尝试均使用独立进程与工作副本。只保留成功路径作为后续会话输入，失败现场和消耗单独保留。
- 快照损坏、运行产物或模型配置改变时停止。正常结束但独立代码验收失败时也停止，不按隐藏验收反复筛选输出。
- 所有尝试固定同一 JAR、模型配置和任务。重试不注入失败诊断，也不修改提示词或 Agent 代码。

这与普通失败恢复不同：普通恢复保留当前轮已有工具进度；评测回退放弃本轮失败工作副本，从上一轮可信边界重新尝试。只适用于可复制的隔离任务，不能据此自动重放外部 API、已写回源项目等副作用。

## 运行

需要 JDK 21、Python 3.10 或以上、本机 Docker、已构建的 `backend-agent-sandbox:local` 镜像及可用模型配置。先按 [使用指南](DEMO.md) 构建项目和镜像。

准备测试包只复制夹具和编译执行器，不请求模型：

```bash
python3 scripts/evaluation/prepare_long_context.py \
  --output reports/long-context/bundle \
  --jar target/backend-engineer-agent-2.1.0.jar \
  --javac "$JAVA_HOME/bin/javac"
```

启动真实模型评测（需要当前用户可以访问 Docker）：

```bash
python3 scripts/evaluation/checkpoint_retry.py \
  --bundle reports/long-context/bundle \
  --output reports/long-context/run \
  --config agent-local.properties \
  --java "$JAVA_HOME/bin/java" \
  --turns 64 \
  --max-attempts 3
```

`--turns` 可缩短本次评测范围；单次调用上限固定为该协议的 50。输出目录必须不存在，避免覆盖旧记录。控制器自身退出后不会在后台自动重启，应先检查仍在运行的子进程与已有记录，不能直接覆盖原目录重跑。

`fixtures/long-context/seed` 是隔离工作区的初始内容，`stages.json` 是用户逐轮输入，`grader-templates` 用于生成外部验收。验收代码不复制进 Agent 的活跃工作区，而是在一次性测试快照中执行，验收结果不反馈给模型。生成器针对随仓库提供的固定回放任务，不是通用日志解析器。

## 记录与校验

- `run/report.json` 保存完成轮次、首次与重试通过、每次结果以及累计成本。
- `run/turn-NN/attempt-NN/` 保存独立会话、请求响应、进程日志、验收结果和轮末快照。
- 累计成本按每次尝试自身 `api.jsonl` 加总，包含失败尝试；不要再次累加子报告继承的历史计数。
- Token 来自已记录的供应商 usage；若进程在请求已发送但 usage 尚未保存时中断，可能存在未记账的请求，应结合供应商账单核验。

不依赖模型 API 的执行器测试：

```bash
python3 -m unittest discover -s scripts/evaluation -p 'test_*.py' -v
```

完整运行记录默认保存在被 Git 忽略的 `reports/`，不随仓库或 Release 发布。
